# 📊 Dataset Architecture & Data Handling — Silkworm Segmentation

This document describes every dataset inside `data/`, their annotation formats, how they are generated, and how to load them via [`src/dataset_multitask.py`](src/dataset_multitask.py).

---

## 📁 1. Folder Layout

Folder names are short and lowercase. Suffixes tell the content: `_bbox` = bounding boxes, `_seg` = segmentation masks, `_augNk` = augmented to N thousand training images.

```text
data/
├── yolo_bbox/        # Raw: images + YOLO bounding boxes + disease class
├── sam3_seg/         # Pseudo-masks generated by SAM 3 from yolo_bbox
├── silkynet_seg/     # Silkynet images (no disease label) — no longer used
├── mixed_10k/        # Augmented 10k train (SAM3 + Silkynet) + fixed valid/test
├── sam3_aug20k/      # ⭐ Per-larva set: train 20k / valid 1k / test 1k / test_real 497
└── test/             # 2 unseen images for quick inference checks
```

Lineage: `yolo_bbox` ──SAM 3──▶ `sam3_seg` ──augment──▶ `sam3_aug20k`
(`mixed_10k` additionally draws from `silkynet_seg`.)

## 🏷️ 2. Dataset Specifications

Class mapping used everywhere (first column of every label file): **`0` = Grasserie (diseased), `1` = Healthy**.

### 2.1. `yolo_bbox` — raw YOLO dataset
- Splits: train 7,978 / valid 499 / test 498 images (`images/`, `labels/`, plus `data.yaml`).
- Labels: `<class_id> <x_center> <y_center> <width> <height>` (normalized).
- Train holds 3,989 distinct originals, each exported twice by Roboflow (suffix `_jpg.rf.<hash>`). Valid and test have one copy per original; no original appears in two splits.

### 2.2. `sam3_seg` — SAM 3 pseudo-masks
- Same file names and split sizes as `yolo_bbox`. Contains **no images** (images live in `yolo_bbox`).
- `masks/`: binary PNG (`0` background, `255` body) · `boundaries/`: 2 px contour masks · `labels/`: polygon labels.
- Masks are pseudo-labels produced by [`utils/sam3_label_from_yolo.py`](utils/sam3_label_from_yolo.py) and are not manually verified.

### 2.3. `silkynet_seg` — Silkynet multi-larvae images
- Sub-folders `larvaTrain` (30), `output20221127` (69), `larvaTest` (69), `20221127` (raw images + JSON).
- About 14 small larvae per image, 1280×720, **no disease label**.
- ⚠️ Mask PNGs store the foreground as value **75**, not 255. Thresholding with `> 127` makes them empty — use `> 0`.

### 2.4. `mixed_10k` — augmented train, SAM3 + Silkynet
- train 9,940 (`silkworm_aug10k_*.jpg`) · valid 110 · test 169 (100 SAM 3 + 69 Silkynet).
- ⚠️ Known issues (kept for reproducibility of past runs):
  - Silkynet-derived training images have **empty masks** (see 2.3) and a forced `Healthy` label.
  - 31% of train images contain both classes but carry a single label (first line).
  - The 69 Silkynet test images are near-duplicates of the sources used to generate train.

### 2.5. `sam3_aug20k` — per-larva dataset (primary)
Built for the production-line goal: **segment every larva and diagnose every larva**. Scenes are composed from SAM 3 larvae (no Silkynet): several larvae per image, healthy and diseased mixed, overlapping larvae, leaf occlusion, photometric changes.

| Split | Images | Source | Notes |
|---|---|---|---|
| `train` | 20,000 | SAM 3 **train** split | synthetic scenes |
| `valid` | 1,000 | SAM 3 **valid** split | synthetic scenes, used to pick `best.pth` |
| `test` | 1,000 | SAM 3 **test** split | synthetic scenes |
| `test_real` | 497 | original SAM 3 test images | real photos, mostly one larva each |

Each split's backgrounds *and* pasted larvae come from the same SAM 3 split, so no larva appears in two splits. About 37% of synthetic images mix healthy and diseased larvae; ~3 larvae per image on average (up to 10).

Per split:
- `images/` — 640×640 JPG
- `masks/` — binary PNG (0 / 255)
- `masks_inst/` — **uint16 PNG, one id per larva** (0 = background)
- `masks_cls/` — **uint8 PNG: 0 = background, 1 = Grasserie, 2 = Healthy**
- `labels/` — YOLO polygons, one line per larva (`<class_id> x1 y1 ...`)
- `aug_previews/` (synthetic splits) — overlays for visual checks

Generation (one call per split):
```bash
python utils/augment_mixed_10k.py --sam3-only --name-prefix aug       --split train --output-dir data/sam3_aug20k/train --goal 20000 --workers 24 --seed 42
python utils/augment_mixed_10k.py --sam3-only --name-prefix aug_valid --split valid --output-dir data/sam3_aug20k/valid --goal 1000  --workers 24 --seed 101
python utils/augment_mixed_10k.py --sam3-only --name-prefix aug_test  --split test  --output-dir data/sam3_aug20k/test  --goal 1000  --workers 24 --seed 101
```
`test_real` is built from `sam3_seg/test` (connected components → instance ids, class from the label file).

Caveats:
- Synthetic scenes are easier than real production images; always also report `test_real`.
- `test_real` has almost no touching larvae, so it measures diagnosis more than separation. A small hand-labelled set of real multi-larva photos would be the most trustworthy test.

## 🔄 3. Loading Data

### Per-larva (primary) — `src/dataset_instance.py`
```python
from src.dataset_instance import InstanceSilkwormDataset
from torch.utils.data import DataLoader

ds = InstanceSilkwormDataset("data/sam3_aug20k", split="train", img_size=256, augment=True, boundary_width=1)
loader = DataLoader(ds, batch_size=8, shuffle=True, num_workers=4)

for image, body, boundary, disease, inst in loader:
    # image    [B, 3, 256, 256]  ImageNet-normalized
    # body     [B, 1, 256, 256]  1 = larva pixel
    # boundary [B, 1, 256, 256]  1 = pixel on a larva contour (computed after resizing, so always thin)
    # disease  [B, 1, 256, 256]  1 = pixel of a Grasserie larva
    # inst     [B, 256, 256]     larva ids, for per-larva evaluation
    pass
```
Splits: `"train"`, `"valid"`, `"test"`, `"test_real"`. Flip/rotate augmentation applies to `train` only.

### Image-level (legacy) — `src/dataset_multitask.py`
`MultitaskSilkwormDataset(data_root, split, img_size, augment)` returns `(image, mask, class_label)` with one label per image (`0` Grasserie, `1` Healthy, `-1` unlabeled). Used by `multitask_vmunet_v1` / `multitask_swinunet`.

## 🛠️ 4. Utilities (`utils/`)

```bash
# SAM 3 pseudo-masks from YOLO boxes
python utils/sam3_label_from_yolo.py --input-yaml data/yolo_bbox/data.yaml --output-dir data/sam3_seg --prompt silkworm --device cuda

# Scene composition / augmentation
python utils/augment_mixed_10k.py --help
```
Flags of `augment_mixed_10k.py`: `--goal`, `--split` (source split), `--sam3-only`, `--same-class-paste` (only for image-level experiments), `--name-prefix`, `--output-dir`, `--workers`, `--seed`. Every generated image also gets `masks_inst/` and `masks_cls/`.

## 🛡️ 5. Integrity Rules

1. **Raw data is read-only:** never edit `yolo_bbox/`, `sam3_seg/` or `silkynet_seg/` by hand; regenerate derived sets instead.
2. **Never commit data:** `data/` and `runs/` are excluded via `.gitignore`.
3. **Strict filename matching:** `images/<stem>.jpg` ↔ `masks/<stem>.png` ↔ `labels/<stem>.txt` share the same stem.
4. **Report valid/test per domain:** SAM 3 single-larva images and Silkynet multi-larvae images behave very differently; do not average them.
